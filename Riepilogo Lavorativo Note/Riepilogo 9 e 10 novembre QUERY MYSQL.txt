# PARTE 1 – CREAZIONE DEL DATABASE

## 1. Creazione e selezione del database

```sql
-- Crea il database Libreria
CREATE DATABASE Libreria;

-- Seleziona il database sul quale lavorare
USE Libreria;
```

## 2. Creazione delle tabelle

```sql
-- Crea la tabella dei generi letterari
CREATE TABLE genere (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(45) NOT NULL
);

-- Crea la tabella degli autori
CREATE TABLE autori (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(45) NOT NULL,
    cognome VARCHAR(45) NOT NULL,
    data_di_nascita DATE,
    nazionalita VARCHAR(45)
);

-- Crea la tabella dei libri
CREATE TABLE libro (
    id INT AUTO_INCREMENT PRIMARY KEY,
    titolo VARCHAR(255) NOT NULL,
    anno YEAR,
    id_genere INT NOT NULL,
    FOREIGN KEY (id_genere) REFERENCES genere(id)
);

-- Crea la tabella delle copie
CREATE TABLE copia (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_libro INT NOT NULL,
    casa_editrice VARCHAR(255),
    numero_copie INT NOT NULL,
    FOREIGN KEY (id_libro) REFERENCES libro(id)
);

-- Crea la tabella intermedia per la relazione
-- molti-a-molti tra libri e autori
CREATE TABLE libro_autori (
    id_autore INT NOT NULL,
    id_libro INT NOT NULL,
    PRIMARY KEY (id_autore, id_libro),
    FOREIGN KEY (id_autore) REFERENCES autori(id),
    FOREIGN KEY (id_libro) REFERENCES libro(id)
);
```

### Logica delle relazioni

- `genere` e `libro`: un genere può essere associato a più libri.
- `libro` e `copia`: un libro può avere più copie registrate.
- `autori` e `libro`: la relazione è molti-a-molti.
- `libro_autori` è la tabella intermedia che collega libri e autori.

Le FOREIGN KEY collegano le tabelle e garantiscono che i riferimenti riguardino record esistenti.

# PARTE 4 – CONCETTI SQL E QUERY DI PROVA

## 12. WHERE – Filtrare i dati

```sql
-- Mostra i libri pubblicati dopo il 2000
SELECT titolo, anno
FROM libro
WHERE anno > 2000;
```

`WHERE` seleziona soltanto le righe che soddisfano una condizione.

## 13. ORDER BY – Ordinare i dati

```sql
-- Ordina i generi alfabeticamente in ordine crescente
SELECT nome
FROM genere
ORDER BY nome ASC;
```

```sql
-- Ordina i generi alfabeticamente in ordine decrescente
SELECT nome
FROM genere
ORDER BY nome DESC;
```

- `ASC`: crescente.
- `DESC`: decrescente.

## 14. LIKE – Cercare una parola

```sql
-- Cerca i libri il cui titolo contiene Harry
SELECT titolo
FROM libro
WHERE titolo LIKE '%Harry%';
```

Il simbolo `%` rappresenta una sequenza qualsiasi di caratteri.

## 15. DISTINCT – Eliminare i duplicati dal risultato

```sql
-- Mostra ogni casa editrice una sola volta
SELECT DISTINCT casa_editrice
FROM copia;
```

`DISTINCT` non cancella i dati dalla tabella: elimina soltanto le ripetizioni nel risultato.

## 16. LIMIT – Limitare i risultati

```sql
-- Mostra soltanto i primi cinque libri
SELECT titolo, anno
FROM libro
LIMIT 5;
```

## 17. COUNT – Contare i record

```sql
-- Conta tutte le registrazioni nella tabella copia
SELECT COUNT(*) AS totale_registrazioni
FROM copia;
```

## 18. GROUP BY – Raggruppare i risultati

```sql
-- Conta quante registrazioni di copie ci sono per ogni libro
SELECT
    id_libro,
    COUNT(*) AS numero_registrazioni
FROM copia
GROUP BY id_libro;
```

`GROUP BY` raggruppa le righe che hanno lo stesso valore.

# PARTE 5 – INNER JOIN E LEFT JOIN

## 19. INNER JOIN – Libri e autori

```sql
-- Mostra il titolo di ogni libro e il nome e cognome dell'autore
-- libro_autori collega libri e autori

SELECT
    libro.titolo,
    autori.nome,
    autori.cognome
FROM libro
INNER JOIN libro_autori
    ON libro.id = libro_autori.id_libro
INNER JOIN autori
    ON libro_autori.id_autore = autori.id;
```

## 20. INNER JOIN – Libri e generi

```sql
-- Mostra ogni libro insieme al suo genere
-- libro.id_genere è collegato a genere.id

SELECT
    libro.titolo,
    genere.nome
FROM libro
INNER JOIN genere
    ON libro.id_genere = genere.id;
```

## 21. LEFT JOIN – Libri, generi e copie

```sql
-- Mostra tutti i libri, il genere, la casa editrice e il numero di copie
-- LEFT JOIN mantiene tutti i libri anche se non hanno copie registrate
-- Se manca una copia, i campi di copia risultano NULL

SELECT
    libro.titolo,
    genere.nome,
    copia.casa_editrice,
    copia.numero_copie
FROM libro
INNER JOIN genere
    ON libro.id_genere = genere.id
LEFT JOIN copia
    ON libro.id = copia.id_libro;
```

## 22. INNER JOIN – Conteggio dei libri per genere

```sql
-- Conta i libri appartenenti a ogni genere
-- INNER JOIN mostra soltanto i generi che hanno libri associati
-- GROUP BY raggruppa i risultati per genere

SELECT
    genere.nome,
    COUNT(libro.id) AS totale_libri
FROM libro
INNER JOIN genere
    ON libro.id_genere = genere.id
GROUP BY genere.nome;
```

## 23. LEFT JOIN – Conteggio dei libri per tutti i generi

```sql
-- Conta i libri per ogni genere
-- LEFT JOIN mantiene anche i generi senza libri
-- COUNT(libro.id) restituisce 0 quando non ci sono libri associati

SELECT
    genere.nome,
    COUNT(libro.id) AS totale_libri
FROM genere
LEFT JOIN libro
    ON genere.id = libro.id_genere
GROUP BY genere.nome;
```

**Concetto fondamentale:** nella query con LEFT JOIN, la tabella scritta subito dopo FROM è la tabella di sinistra. In questo caso è `genere`, quindi tutti i generi vengono mantenuti nel risultato.

INNER JOIN genere

# PARTE 7 – ERRORI INCONTRATI E CORREZIONI

## ERRORE 1 – Database già esistente

**Messaggio:** Error Code 1007 – database exists.

**Causa:** abbiamo provato a creare un database che esisteva già.

**Comando utilizzato per eliminare il database precedente:**

```sql
-- Elimina il database esistente
DROP DATABASE libreria;
```

Successivamente:

```sql
-- Ricrea il database
CREATE DATABASE Libreria;

-- Seleziona il database
USE Libreria;
```

**Lezione imparata:** prima di creare un database bisogna controllare se esiste già. DROP DATABASE elimina tutto il database, quindi va utilizzato con attenzione.

## ERRORE 2 – Anno fuori intervallo

**Messaggio:** Error Code 1264 – Out of range value for column 'anno'.

**Causa:** abbiamo provato a inserire il libro *Orgoglio e pregiudizio* con anno 1813, ma la colonna `anno` era di tipo `YEAR`, che non accetta quell'anno.

**Correzione:** abbiamo sostituito il libro con *Il grande Gatsby*, anno 1925.

```sql
-- Inserimento del libro sostitutivo
INSERT INTO libro (titolo, anno, id_genere)
VALUES ('Il grande Gatsby', 1925, 3);
```

**Lezione imparata:** il tipo di dato scelto per una colonna determina i valori che possiamo inserire.

## ERRORE 3 – ID degli autori e dei libri sballati

**Problema:** durante gli inserimenti abbiamo eseguito più volte alcune istruzioni INSERT. Gli ID AUTO_INCREMENT sono aumentati e sono comparsi record duplicati e identificativi più alti del previsto.

**Causa:** AUTO_INCREMENT assegna automaticamente nuovi ID. Cancellare alcune righe non significa che il contatore riparta da 1.

**Correzione effettuata:** abbiamo ripulito i record duplicati e sistemato gli identificativi, arrivando alla situazione finale:

- Autori: ID da 1 a 8.
- Libri: ID da 1 a 8.

**Lezione imparata:** non bisogna modificare gli ID senza controllare le chiavi esterne e le relazioni che li utilizzano.

## ERRORE 4 – Safe Update Mode

**Messaggio:** Error Code 1175 – Safe Update Mode.

**Causa:** abbiamo tentato di eseguire un aggiornamento degli ID con una query simile a questa:

```sql
-- Tentativo di ridurre gli ID dei libri
UPDATE libro
SET id = id - 16;
```

MySQL Workbench ha bloccato l'operazione perché la modalità Safe Update richiede condizioni di aggiornamento più sicure.

**Lezione imparata:** UPDATE modifica i dati della tabella. Bisogna specificare con attenzione quali righe si vogliono modificare e non cambiare gli identificativi senza verificare le relazioni.

## ERRORE 5 – Duplicazione della chiave primaria

**Messaggio:** Error Code 1062 – Duplicate entry '1-1' for key 'libro_autori.PRIMARY'.

**Causa:** abbiamo tentato di inserire nuovamente le associazioni tra libri e autori, ma le coppie erano già presenti.

La tabella `libro_autori` utilizza una chiave primaria composta da:

- `id_autore`
- `id_libro`

La coppia `(1,1)` era già presente e non poteva essere inserita una seconda volta.

**Correzione:** abbiamo verificato che le otto associazioni esistevano già e abbiamo eliminato dal nostro script il comando di inserimento duplicato.

**Lezione imparata:** una chiave primaria composta impedisce che la stessa coppia di valori venga registrata due volte.

## ERRORE 6 – Alias duplicato in una JOIN

**Problema:** durante una query LEFT JOIN abbiamo indicato due volte la tabella `genere`, ottenendo un errore di alias duplicato.

**Correzione:** la query corretta era:

```sql
-- Mostra tutti i generi, anche quelli senza libri
SELECT
    genere.nome,
    COUNT(libro.id) AS totale_libri
FROM genere
LEFT JOIN libro
    ON genere.id = libro.id_genere
GROUP BY genere.nome;
```

**Lezione imparata:** dopo FROM e LEFT JOIN dobbiamo indicare le tabelle che vogliamo collegare. In questo caso partiamo da `genere` e aggiungiamo `libro`.
